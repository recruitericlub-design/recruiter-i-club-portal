### 3.2. Архитектура связей и сущностей в БД (Prisma Schema) [20]

Разработчик должен использовать существующую структуру таблиц без деструктивных изменений:

1.  **Company (Работодатель):** Хранит реквизиты, телефоны, email и адрес застройщика/производства [12].
2.  **Contact (Кандидаты и B2B-контакты):**
    *   `type = "candidate"`: соискатели. Поля: `country` (страна), `profession` (профессия), `videoUrl` (видеовизитка S3/Cloudinary), `resumeUrl` (резюме PDF), `documents` (JSON-массив паспортов и медсправок), `status` (статус в воронке), `companyId` (связь с работодателем) [12, 20].
    *   `type = "b2b_contact"`: представители работодателя, использующие Личный кабинет [17, 20].
3.  **Deal (Заявка на подбор / Контракт):** Связывает Company и Contact [12]. Содержит поле `customFields` (JSON-строка) [12, 20].
4.  **DealNote (Лента событий):** Хранит логи, системные заметки и историю согласований [12, 20].

### 3.3. Жесткие правила безопасности работы с БД [10, 11, 21]
1.  **Запрещены деструктивные миграции:** Категорическое табу на `prisma migrate dev` и `prisma db push --force-reset`. Модели должны генерироваться через `npx prisma generate` на основе существующей базы.
2.  **Мягкое удаление (Soft Delete):** Запрещено использовать методы `.delete()` и `.deleteMany()`. Все удаления осуществляются через установку флагов `isDeleted: true` и `deletedAt: new Date()` [12, 20, 21].
3.  **Слияние JSON-полей:** Поля `Deal.customFields` и `Contact.documents` хранятся в виде JSON-строк. При обновлении бэкенд обязан сначала считать текущий объект, применить оператор spread `...existing`, внедрить изменения и перезаписать через `JSON.stringify()`, чтобы не затереть историю договоров, оплат и реквизитов [11, 21].
4.  **Запрет на изменение `MessengerSession`:** Таблицу активных мессенджер-сессий (WhatsApp/Telegram менеджеров) изменять на сайте категорически запрещено! [20, 21]

## 4. ИНТЕГРАЦИОННЫЙ WORKFLOW И ЛИЧНЫЙ КАБИНЕТ (CLIENT PORTAL)

### 4.1. Механизм Passwordless-авторизации [17, 18, 21]
Для максимального удобства занятых B2B-клиентов вход в Личный кабинет осуществляется без пароля:
1.  Пользователь вводит номер телефона или Email.
2.  Бэкенд ищет в таблице `Contact` запись, где:
    ```typescript
    const clientContact = await prisma.contact.findFirst({
      where: {
        OR: [{ phone: inputLogin }, { email: inputLogin }],
        type: 'b2b_contact',
        isDeleted: false,
        companyId: { not: null }
      },
      include: { company: true }
    });
    ``` [18]
3.  Если запись найдена, на телефон/email отправляется одноразовый OTP-код (на этапе разработки используется фиксированный мастер-пин `7777`) [18].
4.  После ввода кода генерируется сессионный JWT-токен, содержащий `clientId`, `companyId` и `companyName` [18]. Все данные в личном кабинете фильтруются строго по `companyId` для 100% изоляции информации [19].

### 4.2. Раздел «Мои кандидаты» и 6 этапов воронки легализации
Работодатель видит список привязанных к его компании кандидатов (`Contact.companyId === clientCompanyId && type === 'candidate'`) [21]. Прогресс легализации каждого кандидата выводится через горизонтальный статус-бар на основе поля `Contact.status`:

1.  **Кандидат погоджений** (`status = "screening"` / сорсинг завершен, резюме утверждено).
2.  **Документи в роботі** (началась подготовка пакета для Центра занятости Украины).
3.  **Дозвіл отримано** (Государственный центр занятости выдал официальный документ на работу).
4.  **Віза схвалена** (Консульство Украины выдало рабочую визу типа D-04) [33].
5.  **Трансфер** (сопровождение Молдова — граница — Одесса, кандидат в пути) [35, 38].
6.  **На зміні** (иностранец прибыл на объект, прошел онбординг и приступил к работе) [38].

### 4.3. Автоматический сценарий при нажатии «Утвердить кандидата» [21]
При нажатии клиентом кнопки **«Затвердити кандидата»** в личном кабинете, система выполняет транзакцию:
1.  Меняет статус кандидата в таблице `Contact` на `approved_by_client`.
2.  Автоматически считывает данные работодателя из таблицы `Company` и генерирует проект трудового договора и заявление в Центр занятости по регламентированной форме КМУ.
3.  Сохраняет сгенерированный PDF-файл в Cloudinary и записывает ссылку в `Deal.customFields` в объект `contractDoc` [13, 21].
4.  Создает системную заметку в `DealNote` [12, 20]:
    ```typescript
    await prisma.dealNote.create({
      data: {
        dealId: currentDealId,
        userId: responsibleManagerId,
        type: 'system',
        content: `✅ Клієнт затвердив кандидата ID: ${candidateId}. Сформовано пакет документів для подачі на Дозвіл.`
      }
    });
    ```
5.  Генерирует счет (инвойс) на оплату 2-го транша (25% стоимости) в поле `customFields` [21].
6.  Отправляет вебхук во внутреннюю CRM для информирования проектного менеджера HIREX.

### 4.4. GDPR и сокрытие персональных данных [210]

## 5. ИНТЕРАКТИВНЫЕ ИНСТРУМЕНТЫ ДЛЯ СНИЖЕНИЯ ОТТОКА (DWELL TIME)

Для увеличения времени пребывания на сайте и быстрого прогрева финансовых директоров (CFO) и собственников бизнеса, разработчик должен запрограммировать два калькулятора.

### 5.1. Калькулятор упущенной выгоды от простоя вакансии
Показывает бизнесу, сколько он теряет из-за дефицита линейного персонала.

**Алгоритм расчета:**
$$\text{Дневной простой (грн)} = \frac{\text{Годовой оборот компании}}{\text{Количество рабочих дней (250)}} \times \text{Коэффициент влияния вакансии } (K)$$
*(Где $K = 0.20$ для обычных рабочих, $0.35$ — для сварщиков/операторов ЧПУ).*
$$\text{Итоговая упущенная выгода} = \text{Дневной простой} \times \text{Количество открытых вакансий} \times \text{Дни простою (в среднем 90 дней для Украины)}$$

*   *Входные поля:* Годовой оборот компании (грн), количество сотрудников, число вакансий, средняя зарплата.
*   *Результат:* Анимированная диаграмма финансовых потерь бизнеса. Рядом выводится триггер: *«Услуги HIREX окупаются полностью на 14-й день работы стабильного иностранного сотрудника»*.

### 5.2. Калькулятор налогов и госпошлин нерезидента (Стандарты Украины 2026)

Рассчитывает полные ежемесячные затраты на содержание сотрудника в штате в соответствии с Законом Украины «Про Державний бюджет на 2026 рік» от 03.12.2025 № 4695-IX [84]:

*   **Налоговые ставки на ФОТ:** ПДФО — 18%, Военный сбор — 5%, ЕСВ — 22% [206, 208].
